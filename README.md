# JackSkill（吴杰克 Jack 把自己开源了）

吴杰克 Jack 的个人全量开源实录：收录了他在 B 站、小红书、抖音、微信视频号的真实自媒体数据、全部视频口播逐字稿，以及日常自研的高效生产力工具。

**无需在本地翻找文件或写代码。在任意支持的 Agent 聊天框中，输入一条 `/jack` 即可全盘调用。**

支持环境：豆包、WorkBuddy、Codex、Claude Code，以及所有支持 Agent Skills 的智能体。

## 快速安装

在终端执行一行命令，安装到本机：

```bash
npx -y skills add JackAIStudio/jackskill -g --all
```

## 数据站（可视化）

上面这些数据不用写代码也能看。`docs/` 目录是一个纯静态页面，一打开就是**全部作品**的总表（表格限高、自己在框里滚）。表格下面是四平台表现对照表、一条按平台分开的月度趋势线，最后是一节**口径**——页面上每个比率怎么算出来的都写在那里。

作品表里**每个平台占一列**——竖着扫才能比出高低，把四个数字塞进主题下面那行小字里是比不出来的。那四列显示哪个指标由表头上方的「平台列」切换：播放 / 点赞 / 收藏 / 分享 / 评论。**换指标不换列数**，表格的形制始终不变，扫读的节奏不会被打断；表头是两行的（上行平台名、下行当前指标），滚下去也知道这几列是什么。**点列头排序**（再点一次换方向），所以「哪几期在抖音最能打」点一下抖音列头就出来了——排序只留这一套机制，不再放排序下拉，免得两套机制打架。

表里**最后两列也跟着指标走**，不能写死：

- **合计** = 当前那个指标的四平台之和。早先这里写死了 `summary.views`，于是切到点赞、收藏、分享时，四个平台列都换了，只有合计还在显示播放——一眼看去全是同一批数。
- **末列** = 当前指标 ÷ 播放（点赞→点赞率、收藏→收藏率……）。播放视图没有「播放的效率」，末列固定看收藏率：播放量只说明多少人刷到，收藏才说明多少人觉得以后还要用。**分母和算式都写在表头小字与图例里**，光标停在格子上还会把「收藏 4 ÷ 播放 726」摊开——比率不写清楚除以什么，读者没法验算。

**橙色** = 该指标的效率排进全站前 10%。阈值按当前指标现算，不写死一个数：全站点赞率 1.96%、收藏率 1.02%、评论率 0.40%，根本不是一个量级，共用一个 3% 就会出现「列上标着点赞率、亮的是收藏率的标准」。现在分别是点赞率 ≥8.7%、收藏率 ≥2.6%、分享率 ≥0.7%、评论率 ≥3.0%，并显示在图例里。

想看**一期完整的数字**，点那一行打开右侧抽屉：分平台明细（播放/点赞/收藏/分享/评论/收藏率，列头写明收藏 ÷ 播放）、原片链接、当期逐字稿全文。表格负责「比」，抽屉负责「看」，两个面互不干扰。

（中途试过把明细做成表格里的「展开行」，主题为主、平台为次。撤掉了：一行 44px、一行 400px 会把扫读节奏全打乱，而且它和抽屉装的是同一张表，等于重复造一遍。）

**占位记录不算数**。数据源里有 22 条平台记录五个指标全是 0——这一期在这个平台有记录，但还没采到数。它们仍然在作品表里占一行（「这一期在抖音有记录但还没补数」本身也是这个仓库的真实状态），但**不进任何统计**：不算收录期数，不进中位数，也不参与排序，格子里显示「—」而不是 0。这个判断在 `build-site.mjs` 里做成 `empty` 标记写进构建产物，页面不自己重新实现一遍。早先没有这个标记，抖音的 21 条空记录被当成「真的 0 播放」，把中位播放从 623 拉到了 480——而「平台表现」正是页面上唯一一张替读者下结论的表。

**链接只指向观众能打开的地方**。三分类，写在 `app.js` 的 `urlKind` 里：

- 作品直链 → 「看原片」
- 平台主页 → 「平台主页」（小红书和视频号在数据源里存的就是主页，这两个平台的笔记链接受风控和 token 限制，存下来很快会失效）
- 其余一切 → **不给链接**，显示「未收录原片链接」。观众点进去只有登录墙，挂着一个打不开的链接比不挂更糟。

判据是**白名单**，不是黑名单。这已经栽过两次：第一版只排除 `xiaohongshu.com` 和 `channels.weixin.qq.com` 两个精确的主页域名，92 条 `creator.douyin.com` 被当成了作品直链；改成「排除 `creator.*` + 空路径的主页」之后，`channels.weixin.qq.com/platform/post/list`（视频号创作者后台）又漏了进来。白名单的失效方向是「本来能打开却说不确定」，比反过来安全；漏掉的形态由 `check-data.mjs` 报出来，再补进 `VIDEO_URL` / `HOME_URL`。

修这条判据的同时清了一次数据（2026-10 那次）：94 条指向创作者后台的链接，84 条抖音从**逐字稿头部的「视频原片」行和 git 历史**里回收成了真链，2 条小红书和 3 条视频号后台路径按上面的规矩换成平台主页，剩 8 条本地确实找不到真链，维持原样挂在校验提醒里。

**搜索扫主题、各平台标题和逐字稿全文**。抖音和视频号的标题是「主题 + #话题标签」，所以搜 `#jackskill` 这类标签也能找到；命中来自平台标题时，那一行会把命中的标题显示出来并高亮——不然搜索结果看着像凭空多出来的。

页面上还有一节**口径**，把所有比率的算式、`—` 的两种含义、橙色门槛怎么定、占位记录怎么处理都写清楚。这一节的存在理由很直接：页面上任何一个数，读者都应该能自己验算；验算不出来的数字，等于没公开。

页面没有任何后端，也不连任何外部服务：图表全部手写 SVG，数据在读页面时从同目录的 `docs/data/videos.json` 取。

页面刻意把作品表放在最前、图表放在最后：复盘时真正高频的动作是「找那一期」，不是「看那张图」。图表只保留两条真正会看的——平台对照和增长趋势。

- **数据来源**：`docs/data/videos.json` 是构建产物，由 `data/videos.jsonl` 与 `transcripts/md/` 生成，不是第二份真源。
- **重建**：`node scripts/build-site.mjs`。构建前会先校验数据，有硬伤就中止，不会把坏数据发出去。
- **本地预览**：`cd docs && python3 -m http.server`，然后打开 `http://localhost:8000`。直接双击 `index.html` 不行，浏览器会按 file:// 策略拦掉数据读取。
- **上线**：仓库 Settings → Pages，Source 选 `Deploy from a branch`，分支 `main`、目录 `/docs`。

页面刻意不做的事情，和这里的数据一样重要：

- **不做总量堆叠**。平台是逐年接入的——2023 年只有 B 站，2024 年主要是小红书，2026 年才四平台齐全。堆叠图会把「当时没采这个平台」画成「当时没流量」，所以趋势一律按平台各画一条线，线断了就是那个月没数据。
- **看中位数，不看平均数**。单条爆款能把平均播放拉到失去意义，中位数拉不动。
- **平台色照官方 logo 取，不按印象配**。B 站 `#00AEEC`、小红书 `#FF2442`、视频号 `#FA9D3B`。抖音取黑 `#161823`：它的品牌红 `#FE2C55` 和小红书的 `#FF2442` 几乎是同一个红，但抖音 logo 本体是黑的（青 `#25F4EE` 和红只是故障风描边），用黑既对得上 logo，又能和小红书分开。四个色只在 `docs/assets/app.js` 的 `PLAT` 里定义一处。

## 数据怎么更新

**读写都不依赖任何私有服务器，也不需要任何凭证。** 数据和逐字稿的唯一真源都在这个仓库里，改动只有一条路径：改本地文件 → commit → push。

数据怎么读回来是另一回事：本机浏览器去平台自己的页面（作品页、创作者后台）把指标和链接读回来，是允许的做法，用 Browser Skill、cua-driver 之类都行。被禁的是绕过本地去连自己搭的远程中枢——SSH 到 ECS、查云端 PostgreSQL、FollowJack Hub 那类。判别标准就一句：**数据来源是「平台自己的页面」还是「Jack 私有的聚合服务」，前者可以，后者不行。** 详见 `AGENTS.md` 第 5 节。

不管数据怎么读回来，落点只有 `data/videos.jsonl` 一个地方，页面的构建产物也只是它的投影。

改完之后跑两个脚本：

```bash
node scripts/check-data.mjs    # 校验唯一真源，出错退出码 1
node scripts/build-site.mjs    # 生成页面数据（会先自动校验一次）
```

`check-data.mjs` 守的是这些不变量：

- 每行的 `summary` 必须等于四个平台之和——全站所有数字都是这个口径
- `transcript` 指向的文件必须真实存在
- `id` 不重复、日期格式、指标是非负整数
- 警告项：同一条视频疑似记了两次，两条判据一起用
  - **按标题**：标题相同或包含 + 相隔不超过 30 天
  - **按作品链接**：两条记录引用了同一条作品直链。这条专门补前一条的漏——同一条视频在 B 站和小红书本来就写着不同的标题，按标题查不出来，但一条作品链接只属于一期。补上这条判据时立刻抓到两组早就存在、标题判据一直没发现的重复。
- 警告项：某期一个平台的数据都没有
- 警告项：某平台的链接既不是作品直链也不是平台主页（`creator.*`、`channels.weixin.qq.com/platform/...` 之类）——观众点进去只有登录墙，页面不会把它标成「看原片」
- 警告项：某平台的记录五个指标全是 0（待补录的占位记录）——页面不计入统计，但「收录期数」会虚高

后两类按平台汇总成一条提醒，不会刷屏；提醒里带日期，能直接定位到是哪几期。链接形态的判据（`VIDEO_URL` / `HOME_URL`）和 `docs/assets/app.js` 里的是同一套，改一处要改两处。

`build-site.mjs` 会在构建产物里给这类记录打上 `empty` 标记，页面照着它排除，不自己重新实现一遍判断。构建日志同时打出「各平台覆盖」和「各平台有数据」两个数，差出来的就是待补录的占位记录。

**「一期只算一条」曾经是脚本自动合并的，现在改成只报给你看。** 以前那份 `sync-videos.mjs` 会自动把重复记录合成一条（同一平台保留播放量更高的快照），同时按标题相似度去云端找回当期数据。它已被删除——数据和逐字稿现在完全由本地维护，仓库里没有任何指向外部数据库的代码。

标题相同的判据刻意不用相似度阈值，因为那批英文标题的内容互相能撞到 0.90 以上，会误合。

## 逐字稿文件名就是它的发布日期

`transcripts/md/` 的文件名是 `YYYY-MM-DD_标题.md`，`data/videos.jsonl` 里的 `id`、`date`、`topic` 都从这里来。所以文件名日期写错，代价不是「看着别扭」，而是**页面上那一期会挂在错误的日期上**，跨期比较全部失真。

`check-data.mjs` 会检查「声明的逐字稿文件是否存在」，但**查不出文件名日期本身写错了**——那只能靠人核对。批量整理逐字稿时留意一下。
